神经网络的图经常画成很多小圆点，连线密密麻麻。刚看时很容易觉得，它像一个会自行思考的大脑。

工程上先用更朴素的方式理解：这是一个带着很多可调整参数的计算过程。训练，就是利用数据反复调整参数，让它在某个目标上表现得更好。

## 先用一条直线理解训练

假设要根据某个输入 `x` 预测结果 `y`，最简单的模型可以写成 `y = w * x + b`。`w` 和 `b` 是参数，刚开始可能随便取一个值。

输入一个样本，模型先算出预测值；再和真实值比较，得到误差；最后根据误差调整参数。换成神经网络，计算结构复杂很多，但“预测、计算损失、更新参数”的基本过程仍然成立。

下面的 Python 3 例子只演示单个参数如何被调整，不是完整的深度学习框架：

```python
w = 0.0
learning_rate = 0.1
x, target = 2.0, 6.0

for step in range(5):
    prediction = w * x
    loss = (prediction - target) ** 2
    gradient = 2 * (prediction - target) * x
    print(step, round(w, 4), round(loss, 4))
    w -= learning_rate * gradient
```

`w` 会逐步接近 3，损失随之变小。学习率控制每次走多远，太大可能来回震荡，太小则走得很慢。实际训练中还会使用批次、不同的优化器和学习率策略。

## 多层网络为什么有用

多层结构可以逐步组合信息。图像任务里，浅层可能学到局部纹理，后续层把这些线索组合成更复杂的模式；语言任务则学习上下文中的关联。

这些是帮助理解的描述，不意味着某一层一定对应人类给它起好的概念。模型内部表示通常是分散的，也不能简单把某个参数解释成一条业务规则。

网络还需要非线性变换。如果只是连续做线性变换，很多层仍然可以合成一次线性变换，并不会因为层数多就自动获得更丰富的表达能力。

## 训练和推理，成本不是一回事

训练时要计算损失、保存部分中间结果并更新参数，往往需要更多显存和计算资源。推理主要使用已经确定的参数产生结果，但长上下文、高并发和多轮工具调用也会让成本快速增加。

应用开发者通常不需要从零训练一个大模型。先接一个现成模型，围绕真实任务评估，才知道问题出在哪里。

| 现象 | 可以先尝试 |
| --- | --- |
| 不知道内部制度 | 提供上下文或搭建 RAG |
| 输出格式不稳定 | 明确约束、示例和结构化输出 |
| 某种任务风格长期不符合要求 | 积累高质量样本，再评估微调 |
| 权限判断错误 | 修业务代码和授权边界 |

微调可以改变模型在任务上的行为，但它不是一个随时更新、精确检索的知识库，也不能替代权限校验。

## 模型在训练集上很好，还不够

如果模型只是记住了训练数据，遇到新样本就失效，这就是过拟合。判断它有没有学到能泛化的规律，需要独立验证数据。

可以从减少模型复杂度、增加有效数据、正则化、早停等方向调整。不要机械地理解成“数据越多越好”：重复、错误标注和分布不匹配的数据，可能让训练更贵、效果更差。

对于微调，还应记录基础模型、数据版本、训练参数和评估集。不然两次结果不同，你很难判断到底是哪项变化带来的。

## 动手之前，先给任务设一个终点

“让模型懂公司业务”太抽象。“对二十种工单生成符合格式的处理建议，并在缺少依据时返回待人工确认”就能评估。

先把这个验收集做好。基础模型加提示词已经够用，就不用为了使用深度学习而额外训练；有证据证明它持续卡在某类问题上，再考虑数据和模型层面的投入。
