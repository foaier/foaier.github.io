假设你手里有一批客服工单。老板说：“帮我把这些东西分一下。”这句话还不能直接变成模型需求。

你得先弄清楚：是按已经定好的类别分类，还是希望从一堆数据里发现以前不知道的分组？前者通常是分类，后者才更接近聚类。

## 有没有现成答案，是第一道分界线

如果工单已经由人工标好了“退款”“账号”“发票”，可以拿这些样本训练分类模型。训练时，模型知道每个例子应该属于哪一类。

如果没人标过，只是想看看最近的投诉集中在哪些问题，就可以尝试聚类：把相似的内容聚到一起，然后再由人分析这些组代表什么。

**聚出来的组没有自带的业务含义。** 算法给出“第 3 组”，并不意味着它天然就是“支付故障”。需要抽样阅读、解释和验证。

## 二分类、多分类、多标签怎么选

| 形式 | 工单例子 | 输出特点 |
| --- | --- | --- |
| 二分类 | 是否需要紧急处理 | 两个候选类别 |
| 多分类 | 退款、账号、发票中选一个主类 | 多个类别中选一个 |
| 多标签 | 同时涉及退款和发票 | 一条记录可以有多个标签 |

不要把多标签任务强行塞进多分类。“退货后发票也要作废”本来就同时涉及两件事，强制只留一个标签会丢信息。

多分类还要关心不均衡：账号问题多、发票问题少，模型把小类都错掉，整体分数也可能不难看。除了整体指标，应当看每一类的召回率和混淆矩阵。macro 平均给每类相同权重；micro 聚合所有样本，容易更受大类影响。

## 99% 的准确率为什么可能没用

一万张工单里，只有一百张是真正紧急的。模型全部预测“不紧急”，准确率仍有 99%，但一张紧急工单都没有找到。

这时要看两个问题：挑出来的紧急工单有多少是真的，以及真正紧急的工单找到了多少。对应的是 precision 和 recall。

下面的小例子只用 Python 标准语法：

```python
tp, fp, fn, tn = 60, 40, 40, 9860
precision = tp / (tp + fp)
recall = tp / (tp + fn)
accuracy = (tp + tn) / (tp + fp + fn + tn)
print(f"准确率 {accuracy:.1%}")
print(f"查准率 {precision:.1%}，召回率 {recall:.1%}")
```

准确率达到 99.2%，但召回率只有 60%。这两组数字描述的不是同一件事。

把“判定紧急”的阈值降低，通常能找回更多紧急工单，也会多报一些。阈值要根据漏报和误报的实际成本，在验证集上选择，不能觉得 0.5 顺眼就固定下来。还要注意，模型输出的分数未必是校准过的概率。

## 聚类不是随便跑一次 K-means

K-means 要先定 K，也就是希望分成多少组。它更适合比较紧凑、近似球形的簇；遇到复杂形状、密度差异或离群点时，效果可能不合适。

数值特征的尺度也会影响距离。如果同时使用“金额”和“处理时长”，金额范围大得多，就可能主导结果。标准化前先理解量纲，文本则通常先生成向量，再选择适合这种向量的距离方式和聚类方法。

轮廓系数能提供一个角度，但最终仍要问：这一组是不是围绕同一种问题，拆出来之后是否能指导产品改进？业务上不可解释的漂亮分数，价值很有限。

## 一个可落地的起点

从一小批人工检查过的工单开始，先定清楚类别边界和“其他”类别。分类任务保留独立测试集；聚类任务固定一批抽查样本，每次调整参数后比较结果。

让系统可以选择“不确定，交给人工”，通常比强行给每条数据贴标签更实用。这个出口，也要一起统计数量和处理成本。
