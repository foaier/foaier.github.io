如果你会一点 JavaScript、Java 或其他语言，这一篇可以快速读过。如果从来没有写过程序，也可以跟着做。我们只先掌握后面马上会用到的语法，不要求现在理解 C# 的全部功能。

## 把值存起来，再交给方法处理

变量可以给一段数据起名字。string 保存文字，int 保存整数，bool 保存真或假。var 让编译器根据右边的值推断类型，并不是“没有类型”。字符串放在双引号之间，语句通常用分号结束。

方法像一段有名字的处理过程：输入参数，完成工作，返回结果。后面调用 agent.RunAsync，就是请求一个对象执行某项操作。先理解“谁接收输入、谁返回结果”，比死记方法名称有用。

## 在上一课的项目里做这个练习

把 HelloAi 的 Program.cs 全部替换为下面的代码。这里使用固定规则，不会调用 AI，也不需要任何包。

```csharp
Console.Write("你每天计划学习多少分钟？");
string? input = Console.ReadLine();
if (!int.TryParse(input, out int minutes) || minutes <= 0)
{
    Console.WriteLine("请输入一个大于零的整数。");
    return;
}

string plan = BuildPlan(minutes);
Console.WriteLine(plan);

static string BuildPlan(int minutes)
{
    if (minutes < 20) return "先读一个概念，再用自己的话解释。";
    return "读一个例子，修改一个输入，再检查一次结果。";
}
```

执行 dotnet run，分别输入10、30和abc。你应该得到两种学习建议，以及一次输入错误提示。TryParse负责检查能否转换成整数，if选择处理分支，return结束当前处理。这里的三个输入就是三条简单测试用例。

## 对象为什么经常跟着一个点

对象把数据和操作组织起来。你可以想象一个学习计划对象有主题和时长；一个模型客户端对象则知道服务地址以及如何发送请求。“对象.方法(参数)”就是让这个对象执行方法。

new 通常用来创建对象，using 放在文件开头时用来引入命名空间，让你不用每次写完整类型名。稍后看到 using var client 时，含义有所不同：它会在作用域结束时释放客户端持有的资源。这些用法会在实际代码出现时再解释。

## await 等的是结果，不是把电脑卡住

模型调用要经过网络，结果不会立即出现。名称以 Async 结尾的方法通常返回 Task，表示一项将来完成的工作。await会等待这项工作的结果，并在等待期间把线程使用权交还给运行环境。

这不等于任务已经放进了持久化队列。程序退出或进程崩溃时，普通 await 不会自动帮你恢复任务。后台任务与检查点会在进阶章节单独学习，先不要把“异步”和“永不丢失”混为一谈。

## 看懂错误也是编程的一部分

编译错误发生在程序开始运行之前，比如少了分号、类型不匹配、方法不存在。运行错误发生在执行过程中，比如文件不存在、网络连接失败、密钥无效。先区分这两类，再决定是修改代码还是检查环境。

后面的示例会在缺少环境变量时主动抛出带说明的异常。throw是让程序明确报告问题，try/catch可以在入口把它转换成读得懂的错误提示。不要把所有异常都吞掉后打印“成功”，那会让排错更困难。

## 自己改一个地方

给示例增加第三个分支：学习时间达到60分钟时，建议完成一个小实验。依次输入10、30、60和0，确认分支和校验都按预期执行。

参考做法是在“小于20”的判断之后增加“小于60”的判断，最后返回实验建议。如果顺序写反，较大的范围可能先匹配，导致后面的分支永远执行不到。这个思路以后会直接用在 Agent 工作流的条件判断里。
