企业产品迭代时，旧系统的数据通常需要进入新的业务系统。不同产品有各自的业务逻辑和数据结构，客户侧还可能存在定制开发。把迁移逻辑写死在单个工具里，很难覆盖这些差异，也容易让迁移过程依赖大量人工操作。

在数据迁移中心项目中，我们将迁移过程拆成规则配置、数据准备、迁移执行和结果核对几个环节，让产品差异和租户差异可以通过配置表达。

## 先把差异变成规则

迁移规则覆盖表字段映射、数据转换、过滤条件、固定值、枚举值和插件取数等场景。产品规则可以作为默认配置，租户规则继承产品规则后再做调整，并保持租户之间相互隔离。

这让不同产品和客户的迁移要求能够在同一套流程中表达，也为后续执行工具提供了清晰的规则来源。

## 执行前检查并准备数据

迁移前的数据巡检用于发现缺失值、重复记录和格式错误等问题。数据准备环节根据迁移规则和目标系统结构完成清洗、转换与映射，降低问题数据进入新系统的风险。

## 执行后核对结果

迁移完成后，系统生成核对报告，呈现迁移总量、成功与失败数量以及差异详情，供项目人员确认迁移结果。规则也可以解析并同步到 SQLite 数据库，由对应的迁移工具读取和执行。

## 技术组成

该项目使用 Vue、ABP vNext、ASP.NET Core Web API、Entity Framework Core、Quartz.NET、SQL Server 和 SQLite。配套的交付工具还覆盖数据迁移、Excel 导数、组织架构调整和数据库操作等场景。

将配置、执行和核对拆开之后，规则更容易复用，迁移过程也更容易检查和追踪。这是建设数据迁移工具链时一个直接而实用的经验。
